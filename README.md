# FoG Farmer

Асинхронный Telegram-фармер для `@fogmmobot` с отдельной панелью управления.
Игровая сессия работает через Telethon, панель администратора — через aiogram,
состояние и статистика хранятся в SQLite.

## Требования

- Python 3.11+
- Telegram `api_id` и `api_hash`
- токен отдельного управляющего бота
- Telegram ID администратора

## Локальный запуск

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows: .venv\Scripts\activate
python -m pip install --require-hashes -r requirements.lock
```

Скопируйте `.env.example` в `.env` и заполните значения. Сам Python не читает
`.env` автоматически: экспортируйте переменные окружения или передайте файл
контейнеру. Для локального хранения задайте `FOG_DATA_DIR` на доступный каталог.

Перед первым запуском авторизуйте игровую Telegram-сессию в интерактивном
терминале. Команда запросит номер телефона, код Telegram и пароль 2FA, если он
включён. Используйте тот же `FOG_DATA_DIR`, что и для приложения.

```bash
python authorize.py
python main.py
```

`main.py` использует уже авторизованную сессию и не запрашивает данные через
панель бота. При сброшенной авторизации повторите `python authorize.py` после
остановки приложения.

Обязательные переменные:

- `TELEGRAM_API_ID`
- `TELEGRAM_API_HASH`
- `CONTROL_BOT_TOKEN`
- `ADMIN_TELEGRAM_ID`

Необязательные: `FOG_DATA_DIR` (по умолчанию `/app/data`) и
`FOG_CHARACTER_NAME` (по умолчанию `Kombat`).

## Docker

```bash
docker build -t fog-farmer .
# Выполните один раз для нового volume или после сброса авторизации:
docker run --rm -it --env-file .env -v fog-farmer-data:/app/data fog-farmer python authorize.py
# Дальнейшие запуски используют ту же сохранённую сессию:
docker run --rm --env-file .env -v fog-farmer-data:/app/data fog-farmer
```

Каталог данных содержит SQLite, Telethon-сессию и журналы. Не добавляйте его в
образ и не публикуйте: файлы сессии дают доступ к Telegram-аккаунту.

## Проверки

```bash
python -m pip install --require-hashes -r requirements-dev.lock
python -m unittest discover -s tests
python -m ruff check .
python -m mypy .
```

CI выполняет те же проверки на Python 3.11 и 3.12 в Linux и Windows.
Mypy работает в полном строгом режиме для всего кода приложения.

## База данных

Схема обновляется при старте и имеет номер в `PRAGMA user_version`. Перед
развёртыванием новой версии остановите процесс и сохраните вместе файлы
`fog_farmer.sqlite3`, `fog_farmer.sqlite3-wal` и `fog_farmer.sqlite3-shm`, если
они существуют. Не копируйте работающую SQLite по одному файлу.

## Гарантии обработки и восстановления

Входящие игровые события обрабатываются последовательно. Заполнение очереди
приостанавливает приём до освобождения места; результаты боя не удаляются.
Учёт урона и наград отделён от нажатия кнопок: устаревшая карта или ход не
получают новое действие, изменение клавиатуры не обучает боевую модель повторно.
Возврат на уже посещённую клетку учитывается как новый переход. Таймерные
правки и повторная доставка сообщения не разрешают повторное нажатие кнопки.

Запрос карты ограничен 10 секундами. Для состояния без ответа повтор разрешён
через 30 секунд и выполняется watchdog с учётом его таймаута. После трёх
безуспешных попыток восстановления фармер останавливается с объяснением причины.
Telegram FLOOD_WAIT сохраняется и соблюдается после перезапуска.

Остановка отменяет и ожидает фоновые задачи, затем закрывает Telegram-сессию
даже при ошибке сохранения статистики. Блокировка сессии удерживается до
завершения очистки. Если очистка не закончилась, новый запуск запрещён;
повторите «Стоп». Неожиданная ошибка фоновой задачи завершает фармер и
передаётся в панель управления.

## Допустимые задержки

Все значения должны быть конечными, неотрицательными; максимум не меньше
минимума. Интервалы сохраняются одной транзакцией.

| Настройка | Максимум |
|---|---:|
| Перемещение, открытие атаки, выбор цели, навык | 300 секунд |
| Короткая пауза | 3600 секунд |
| Передышка между циклами | 1440 минут |

Некорректные старые значения заменяются стандартным диапазоном при загрузке.
В интерфейсе передышка задаётся в минутах, остальные задержки — в секундах.

## Обновление зависимостей

`requirements.txt` и `requirements-dev.txt` задают допустимые прямые зависимости.
Lock-файлы фиксируют весь проверенный набор и хеши пакетов; Docker и CI используют
именно их. Обновляйте оба файла вместе, затем выполняйте тесты и `pip check`.

```bash
python -m pip install pip-tools==7.6.1
python -m piptools compile --generate-hashes --strip-extras --no-emit-index-url --no-emit-trusted-host -o requirements.lock requirements.txt
python -m piptools compile --generate-hashes --strip-extras --no-emit-index-url --no-emit-trusted-host -o requirements-dev.lock requirements-dev.txt
```
